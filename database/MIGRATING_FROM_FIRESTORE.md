# TiDB storage and legacy Firestore import

The application stores business data, WhatsApp OTP challenges, OTP rate limits, verified phone numbers, and anonymous API sessions in TiDB. The deployed application does not use Firebase Authentication or access Firestore.

The Firestore migration scripts below are optional, one-time import tools for existing data. They read Firestore and insert/update rows in TiDB; they do not delete or modify the Firestore source. Avoid running them again after cutover unless you intend to overwrite matching TiDB rows with legacy data.

## Setup

1. Run `database/tidb_schema.sql` in TiDB Cloud to create the application and OTP tables.
2. Configure server-only environment variables locally in `.env` and in Vercel:
   - `TIDB_HOST`
   - `TIDB_PORT`
   - `TIDB_USER`
   - `TIDB_PASSWORD`
   - `TIDB_DATABASE=kravent_bike`
   - `TIDB_SSL_CA` when required by the cluster. In Vercel, set PEM contents (with escaped newlines), not a local file path. A local CA file path only works when that file exists in the server environment.
   - `ADMIN_ACCESS_PIN` and `STAFF_ACCESS_PIN` (each exactly 4 digits), stored only in server environment variables. Choose new PINs; do not reuse the former client-side PINs.
   - `WHATSAPP_OTP_SECRET` (at least 32 characters)
   - Meta WhatsApp Cloud API settings used to send OTP messages
3. If `app_sessions` already exists, add these columns once before deploying the role-protected API: `ALTER TABLE app_sessions ADD COLUMN role VARCHAR(16) NOT NULL DEFAULT 'customer'; ALTER TABLE app_sessions ADD COLUMN role_expires_at_ms BIGINT UNSIGNED NULL;`
4. Staff/owner access is verified on the server, expires after 12 hours, and is temporarily locked after five incorrect PIN attempts. No Firebase client configuration, Firebase Authentication, or Firestore rules are needed by the deployed application. Anonymous bearer tokens are generated by the API; only their hashes, expirations, and server-verified roles are stored in the `app_sessions` TiDB table.
5. Deploy the application and verify it can load and save data, request an OTP, and verify a phone number before customer booking.

## Optional one-time import from Firestore

The optional legacy import scripts still read Firestore. To run one, configure `FIRESTORE_DATABASE_ID` and `FIREBASE_ADMIN_SERVICE_ACCOUNT_JSON` in the local `.env`, along with the TiDB connection variables. Then either:

- Run `npm run export:tidb-sql`, then execute the generated `database/firestore-to-tidb.sql` in TiDB Cloud; or
- Run `npm run migrate:tidb` to copy directly into TiDB.

The generated SQL may contain customer data and is git-ignored. These scripts only migrate the four legacy business collections (`bikes`, `bookings`, `expenses`, and `financial_settings`); OTP challenges and verified-phone records are short-lived and are not imported.
